# AI 的定位与提示词库

## 一、三个该做的角色，一个不该做的

| 角色 | 做什么 | 提示词方向 |
|---|---|---|
| **追问者** | 挑术语、要例子、问为什么、问反例 | 苏格拉底式，不给答案 |
| **生成器** | 出题、制卡、排期、造变式题、做混排 | 结构化输出，可指定格式 |
| **诊断者** | 错因归类、校准分析、指出缺失 | 只看用户的作答文本，不提前给正解 |
| ~~写手~~ | ~~直接给答案、替用户写总结~~ | **禁止** |

判定标准很简单：**AI 做完之后，用户本人能不能复述出来？** 不能，就是替代了思考。

## 二、三条红线（要写进产品的说明里）

1. **先生成，后辅助**：任何任务先独立做，AI 只做批改与追问
2. **答案不算产出**：不看 AI 文本重写一次，才算完成
3. **事实必核查**：AI 给的数字和引用一律二次检索

## 三、本地规则引擎 vs 真大模型

产品里内置的是**规则引擎**，不是大模型。这是刻意的设计决定：

- 离线可用、行为可复现、不会幻觉
- 逼用户**先在没有 AI 的情况下完成提取**——这一步才是学习发生的地方
- 真 AI 的用法交给提示词库页：用户复制粘到任意大模型

不要为了"显得智能"把内置学伴换成调 API 的聊天机器人，那会直接违反"AI 只做陪练"。

## 四、提示词库（可直接复制给用户）

按方法组织，每条给「AI 角色 + 提示词全文」。

### 主动回忆
> 根据下面这段材料（附原文）出 10 道只凭回忆才能答的简答题，答案后置。答完后按「精确 / 近似 / 错误 / 未答」四级评分，指出每个近似答案是哪个关键词缺失。

### 间隔重复
> 根据艾宾浩斯间隔效应，为以下 20 张卡片生成复习日期序列，目标保持期为 30 天。每轮给出「再次 / 困难 / 遗忘」三种按钮对应的下次日期。

### 卡片生成
> 把下面内容拆成最小知识单元，输出 CSV，列为 front,back,type,example，type 只取 definition/equation/example 之一。背面不得照抄原文整句，必须给一个具体例子。

### 测试效应
> 先只给问题不给我答案。我答后先问我「你有多大把握」，再让我在不看答案的前提下再答一次。最后才给答案并标出我两次答案的差异。

### 交错练习
> 从【集合 A/B/C】各取 4 题随机混合成一套，但每题前加「先判断该用哪条规则」的选项。批改时区分分类错误与计算错误。

### 费曼讲解
> 你是完全不懂这个话题的 5 岁小孩，我下面给你讲【概念】。你只能根据我讲的内容追问：「这句话什么意思」「能换个例子吗」「你说的 X 和 Y 有什么不一样」。发现我用了术语或逻辑跳步就立刻打断，不要替我补充答案。

### 精细提问
> 不要直接解释。只连续问我「为什么」「这个前提从哪来」「如果去掉这个条件结论还成立吗」，每问一句等我自己答。

### 自我解释
> 我下面逐句解释解题过程。你只核对每一步的前提是否真实、规则应用条件是否满足，并列出我含糊的因果连接。不要给我完整解法。

### 康奈尔线索栏
> 根据我的笔记右侧内容，为每条写一个引导提问，不要写答案。提问必须能触发回忆，不用「什么是」这类只要再认的问法。

### 概念图
> 用 Mermaid 输出概念图，节点只用名词短语，边必须带关系词（导致 / 需要 / 反例是 / 前提是）。不要放射树，要标出跨分支关系。

### 错题归因
> 只根据我的作答文本分析错因类别（事实 / 条件 / 推理 / 表达），不要看我会不会。给出 2 道同一错因变式题与 1 条最小修正提示。

### 元认知复盘
> 这是我的预测正确率与实际正确率。计算校准误差，标出我系统性高估或低估的题型，并给出下周的抽样自测方案。

### 模拟口述
> 扮演面试官连续追问 8 分钟，只针对我回答中的概念定义与例子边界追问。结束后给我 3 个我答得最含糊的词。

### 防幻觉
> 只基于以下材料回答，并逐条标注引用片段。如果你不确定，说不知道，不要补全事实。所有数字必须能在材料中找到出处。

## 五、把提示词接到产品上

- 提示词库页：卡片式展示，**一键复制**
- 浮动学伴面板：本地规则引擎，两模式（只追问 / 批改）
- 批改模式下，学伴要对照当前题目的 `keys` 指出缺失，并附一句"我给的反馈不算你的产出"

## 六、三大风险（要在产品里向用户说明）

| 风险 | 表现 | 对策 |
|---|---|---|
| **幻觉** | 说得越流畅越可能错 | 数字与引用二次检索；用"防幻觉"提示词 |
| **元认知偷懒** | 答案替代思考，产物完整但本人复述不出 | 先独立作答；不看 AI 文本重写一遍 |
| **认知卸载** | 记住"去哪查"而不是"内容本身" | 核心概念离线可复述；每天留一段无 AI 时间 |

**自测问句**（可放界面上）：关掉网络，你能复述出今天学的三个概念吗？
## 七、流式对话的四个坑（「回答到一半就没了」的全部成因）

接 OpenAI 兼容接口、开了 `stream: true` 之后，最容易出的一类 bug 是**回答说到一半停住，而且什么提示都没有**。
逐个排查这四处，基本能覆盖：

| # | 坑 | 症状 | 判据 / 修法 |
|---|---|---|---|
| 1 | **`max_tokens` 太小** | 句子断在半截，随后安静结束 | 思考模型的 `reasoning_content` 与正文**共用**这个预算。默认给 1024，思考一长正文就只能写几句。默认改 4096，并在设置面板暴露出来 |
| 2 | **`finish_reason` 被丢掉** | 服务端明明报了 `length`，前端当正常结束 | 很多实现里 `finish` 回调是个空函数。必须接住：`length` = 撞到上限，`content_filter` = 被内容策略掐断，两者都要在气泡下方明说 |
| 3 | **超时按「总时长」算** | 长回答/慢模型必被砍，且刚好砍在中间 | `setTimeout(() => ctl.abort(), 60_000)` 从请求发出就计时，不因为「还在持续收 token」而续期。改成双阈值：**首包超时**（请求→第一块数据）+ **空闲超时**（两块数据之间），每收到一块就 `bump()` 重新计时 |
| 4 | **干净地断流 = 静默截断** | 上游半路关连接时，浏览器只给 `reader.read()` 的 `done: true`，不报错 | 流结束时检查是否收到过 `[DONE]` 或任一 `finish_reason`；两者都没有就标 `interrupted`，告诉用户「上游没有正常收尾」，别让它看起来像正常结束 |

还有两个次生问题：

- **出错时把已生成的内容删掉**。`catch` 里 `wrap.removeChild(body)` 会让用户眼看着半句话消失。正确做法：保留正文 + 下面另起一行说明，「已保留 N 字」。
- **逐 token 写 DOM**。`el.textContent += s` 每个 chunk 触发一次布局 + `scrollTop` 读取，长回答会明显卡顿（体感像卡死）。用 `requestAnimationFrame` 合并到每帧一次。

恢复手段：撞到上限/被打断时给一个**「接着写」按钮**——把已有回答留在 `messages` 里，追加一句
「接着上面那段没写完的回答继续写，从断点处接上，不要重复已写过的内容」，再发一次即可，不需要额外接口。

**验收用什么造**：本地起一个 mock，用三种模式跑（脚本见项目里的 `mock-llm.py` + `verify-npc.py`）：

```bash
python mock-llm.py --mode truncate --port 8891   # 报 finish_reason=length
python mock-llm.py --mode drop     --port 8892   # 吐几个字后掐断连接
python mock-llm.py --mode slow --interval 1 --total 14 --port 8893   # 慢流
```

关键断言：慢流那项把配置超时压到 10 秒、让流跑 14 秒 —— **旧的总时长计时必挂，改成空闲计时才过**。
这条断言比读代码更能证明修好了。
