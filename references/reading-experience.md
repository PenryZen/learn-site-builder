# 长篇精读站：阅读体验三件套

适用于**单章几千字、用户要连续读**的站点（教材精读、论文带读、名著伴读）。这时瓶颈不再是「有没有关卡」，而是**眼睛累不累、公式看得清不清、能不能听着读**。

三件事按收益排序：公式排版 → 正文字体 → 朗读。每件都附了验收方法，别只看代码跑通就算完。

---

## 一、公式：长的独立成行，分数要立起来

### 问题

行内公式一多，句子会被撑成一团：`f(x)=...` 挤在字缝里，上下标缩得看不清，分数横躺着更难辨。长公式必须脱离句子独立成行。

### 判定：什么样的公式该升级为独立行

**按原文长度判，不能按转成 LaTeX 之后的 tex 判。** 这是最容易踩的一处：
`a/b` 经 `fracify` 变成 `\frac{a}{b}` 后长度凭空翻倍，`∂/∂x` 这种 4 个字符的表达式
也会命中「含 `\frac`」那条，被抬成独立一行 —— 于是一句正常的话被切成一段一段，
满屏都是孤立的小公式（实测某章一页里 9 个）。

| 条件（都在**原文**上量） | 阈值 |
|---|---|
| 含 `∫ ∮ ∑ ∏` 等大运算符 | 字符数 ≥ 14 |
| 含 `=` | 字符数 ≥ 18 |
| 原文里就写着 `\frac` | 字符数 ≥ 10 |
| 其余 | 字符数 ≥ 30 |

```js
function isLongMath(raw, tex) {        // raw = 原文片段，tex = 转换后的 LaTeX
  var t = String(raw).replace(/\s+/g, "");
  if (/[∫∮∬∭∑∏]/.test(t) || /\\sum|\\int|\\oint|\\prod/.test(tex)) return t.length >= 14;
  if (t.indexOf("=") >= 0) return t.length >= 18;   // 等式链才值得整行
  if (/\\frac|\\dfrac/.test(t)) return t.length >= 10;
  return t.length >= 30;
}
```

**反向保护**：升级前看左侧余量。前文（去掉空白）不足 6 字，或整行不足 30 字时**不升级** ——
否则「用 √(1−v²/c²) 亲手算出」会被劈成三行，比原来更难看。

```js
function fitsLine(txt, at) {          // at = 公式在行内的偏移
  var before = txt.slice(0, at).replace(/\s/g, "");
  return before.length >= 6 && txt.replace(/\s/g, "").length >= 30;
}
// 满足 isLongMath(raw, tex) && fitsLine(...) 才走 displayHTML()
```

**经验值**：改对之后，同一本书的块级公式从 880 个降到 329 个，而页面反而更好读。

### 候选字符集：漏一个字符，公式就被劈成两半

自动识别公式靠「候选字符连续片段」。凡是能翻成 LaTeX 的字符，**必须同时属于候选字符集**，
否则它会把公式劈开，两半各排一块，读者看到的是：

```
i^i = e^{i log i} = e^(i·
½
πi) = e^{−π/2} = 0.207879576
```

最容易漏的是**没有 LaTeX 命令名的那些**：`½ ¼ ¾ ⅓ ⅔ …`（分数字符）、`± × ÷ ¬`、
`…`（U+2026，常写在 `Q_{f…h}` 这种指标范围里）、`⟵ ⟶ ⟹ ⟺`，
以及**补充平面**的数学字母 `𝒞 𝒮 𝔤`（U+1D400–U+1D7FF，得先用 NFKC 退成普通字母）。

写成不变量守住它：

```js
// 遍历 0x20..0x2BFF，凡 MT.tex(ch) !== ch 的字符，都必须能进 MT.segs("a"+ch+"b")
// 例外只有 # % & 三个字面字符
```

### 函数名要排正体，空格不能被吃掉

- `log i` 若按斜体字母逐字排，会连成「logi」。转 LaTeX 时把
  `sin cos tan log ln exp lim det max min sup inf arg gcd arcsin sinh …` 换成 `\log` 等命令，
  后面补一个空格免得和紧跟的字母粘成 `\logi`；前后都要求非字母，别把 `logistic` 拆坏。
- 候选片段会带上首尾空格（空格也在候选集里），而 KaTeX 会吞掉空格 —— 汉字和公式就贴在一起了。
  渲染前把首尾空格剥出来留在正文里。

### 上下标：括号是「分组」还是「记号」

源文里两类写法长得一样，处理必须分开：

| 写法 | 语义 | 转法 |
|---|---|---|
| `e^(2πi)`、`w^(1/2)` | 括号只是分组 | `e^{2\pi i}`、`w^{\frac{1}{2}}`（**去掉**括号） |
| `Q_(ab)` | 张量的对称部分 | `Q_{(ab)}`（**保留**括号） |
| `Q_[ab]` | 张量的反对称部分 | `Q_{[ab]}`（**保留**方括号） |

判断依据是统计出来的：全书 `^(...)` 167 处全是分组，`_(...)` 7 处、`_[...]` 17 处、
`^[...]` 5 处全是张量记号。既然 `^` 和 `_` 的用法不同，就别用同一条规则。

**多字母上下标是「指标」，不是乘起来。** `Q_ab` 必须排成 `Q_{ab}`（只吞一个字符会变成
`Q_a b`，意思全错）；`g_μν` → `g_{\mu\nu}`、`T^ab` → `T^{ab}`、`x^10` → `x^{10}`。
全书 266 处下标、54 处上标都是这个意思。三条约束：

- **必须在字符映射之前做**：映射之后希腊字母已变成 `\mu` 这样的命令，认不出连写
- 只收「纯字母」或「纯数字」的连写；数字+字母混排（`2π`）可能是乘积，不要动
- 只对 `_` 和 `^` 后面的**连续**字符生效，`x^2 y` 这种分开的不受影响

**识别层也要跟着放宽**，否则整段不会进公式通道、原样显示：

```js
// x^2 / T^{a} / w^(1/2) / Q_[ab]：括号、方括号、反斜杠都要认
if (/[\^_]\s*[{\[(A-Za-z0-9\\]/.test(t)) return true;
```

漏掉 `(` 的后果就是第 5 章 35/49 页那样：整页 `w^(1/2)`、`w^(1/n)`、`(w^(1/z))^z` 全是原文。

### 分数：`a/b` 要还原成 `\frac` —— 但只在独立行里

正文里的公式常是 OCR 出来的线性写法 `f(x)/y`、`∂³f/∂x²∂y`、`n!/(2πi)`，直接渲染就是一长条斜杠。
要还原成上下结构，**不能靠正则**（嵌套括号会崩），要做 token 扫描：

1. `toks()` 切分为 `cmd / op / wd / grp / sp`
2. `leftBound()` 向左收因子，遇空格、二元算符、外层括号即停
3. `rightBound()` 向右收因子；`matchFwd` / `pairLeft` / `pairRight` 配平 `\langle|`、`\lvert`
4. `stripParen()`：`(a+b)/(c+d)` 去掉多余括号再包 `\frac`
5. `DIFFOP`（`\partial` `\nabla` `\delta`）特判：`iħ∂/∂t` 的分子只取 `∂`，别把 `iħ∂` 整个搬上去
6. `INFIX` 表（`\cdot \times \pm \le …`）阻断跨界，防止吞掉运算符右侧
7. `mapGroups()` 先递归括号内部，再处理外层

**但行内不要立分式。** `\frac` 会把行高撑高，正文变成一行高一行矮 —— 又是一种「断层」。
行内渲染前做一次反悔：分子分母都简单（不含 `+ − = < >`）时退回斜杠写法，
`∂/∂x`、`1/2`、`f′(0)/1!` 都保持一行高。行高齐平是长文可读性的底线。

### 超长等式链：按 `=` 折行

比栏宽还长的等式链，靠横向滚动读就是被切断。按**顶层 `=`**（跳过 `{}` 内部）折成
`\begin{aligned} LHS &= RHS1 \\ &= RHS2 …\end{aligned}` —— 书上本来就这么排。
tex 短于 110 字符不动，链上少于 3 段也不动。

兜底还有一层：渲染完量一次 `scrollWidth > clientWidth`，按比例收字号（下限 0.62 倍），
缩放要在渲染后做（`fitWideMath()`），并且阅读模式切换、窗口 resize 之后都要重算一次。

### 别让读者看见「渲染失败」

独立行渲染失败时**不记失败、自动退回行内**，否则一个坏公式会在页面中央留一块空白。
紧跟的句读要**整串**收进同一个 `<span>`（`。，、；：？！…·」』）】》%`），
只收一个字符的话，「0.207879576…。」会掉到下一行开头，看起来就像被切断了。

### 验收

写一个 `verify-math.js` 守住四件事，任何一项退化就非零退出：

1. 不变量：候选字符集没漏（`# % &` 除外）
2. 全书扫描：没有被劈成两块的公式（两个块级块之间夹着数学字符）
3. 渲染失败数 ≤ 2（只剩 `∞^k^∞^n` 这种本身不合法的记号）
4. 钉子页快照：`ch5 p34` 必须 1 块（曾是 2 块）、`ch10 p24` 必须 0 块（曾是 9 块）

浏览器侧另外量两件事：

- 全部 2367 页逐页翻，`scrollWidth - clientWidth > 2` 的元素数必须为 0
- 同一页里所有 `.mth` 的高度集合应当只有一个值（行高齐平）

## 二、正文：中文字体必须子集内嵌

### 问题（最容易误判的一处）

CSS 写 `font-family:"Kaiti SC","STKaiti",...`，在 Safari 上**静默回退到宋体**。原因是系统楷体属于 macOS 的**按需字体资产**，WebKit 用族名、PostScript 名、中文名都匹配不到；Chromium 同样解析不到，只是不容易察觉。

**`document.fonts.check()` 会假阳性**——它返回 `true` 也不代表真的用上了。必须像素级对比，或用 WebKit 实测截图确认。

### 做法

```python
# 1. 扫全站字符（数据文件 + JS 字符串里的标点、希腊字母、上下标都要收）
# 2. 从系统 TTC 取两个 face：Regular=0 / Bold=3
tc = TTCollection(Kaiti_ttc)
# 3. fontTools subset → woff2（brotli）→ base64 写进 css
```

- `@font-face` 用**自定义族名**（如 `KaiSubset`），别复用系统名，避免和系统字体打架
- 接入顺序：`katex.css → kai-font.css → styles.css`（字体定义要在使用前）
- 单文件打包时把 `kai-font.css` 排进 CSS 数组

**找字体这一步有个陷阱**：macOS 在 `Fonts/Subsets/` 下放了一个 58KB 的「按需字体占位包」，
`mdfind -name Kaiti.ttc` 会**先**返回它。拿它子集化只能得到 3KB 字体、大半字缺字形，
页面上看起来「换了字体」其实是回退字体。判定只认一条：**完整楷体约 100MB**，
`build-kai-font.py` 现在会跳过 `Fonts/Subsets/` 且只收 ≥5MB 的候选。
生成后看一眼输出里的 KB 数：1000 多字的子集，400 档应在 200KB 以上，只有 3KB 就是拿错了文件。

### 脚手架已经内置这一层

`assets/scaffold/kai-font.css` 是给 demo 内容生成好的子集，`index.html` 里在 `styles.css` **之前**引入，
`styles.css` 里 `--kai:"KaiSubset",…`，只作用于 `.rd-p / .note-q / .note-a`。
换内容后重跑一次（在项目根目录）：

```bash
python3 <skill>/assets/reading/build-kai-font.py --root . --out kai-font.css
```

跳字、缺字的症状是「个别字明显换了字形」，扫全站字符就是为了避免它，别只扫 `data.js`。

### 只给长文用，别全站套

楷体字面比屏方小，且横竖对比弱，标题/按钮/卡片标题用它会糊成一片。**只作用于长文 prose**（原文译文、讲授块、注释），标题与交互元素保持屏方：

```css
.rd-p, .note-a, .note-q { font-family: var(--kai); }
```

### 字号光学校准

实测 **16px 楷体 ≈ 14px 屏方**。照原字号直接换字体，读者会觉得「变小了」。按比例上调，并给楷体略松的行高：

```css
--kai: "KaiSubset","Kaiti SC","STKaiti","KaiTi","楷体",serif;  /* 排除繁体楷体，别串字 */
.rd-p { font-size: 16.5px; line-height: 1.95; letter-spacing: .01em; }
```

### 验收

- 用 **WebKit**（不是 Chromium）以 `file://` 打开，读 `document.fonts` 确认两档 `status === "loaded"`
- 截图肉眼比对：楷体笔画有粗细变化、横细竖粗；宋体横竖等粗
- 窄屏（420px）确认无横向溢出——楷体字宽略大，容易挤爆

体积参考：2887 个字符 → 两档 woff2 共约 1.5MB → base64 后约 2MB。单文件 HTML 从 13.4MB 涨到 15.3MB，可接受。

## 三、朗读：三引擎 + 自动降级

### 先认清硬限制（别浪费时间试）

**微软 Edge 神经语音（晓晓）无法从浏览器直连。** 它的 WebSocket 接口强制要求 `Sec-MS-GEC` 自定义请求头，而浏览器规范禁止脚本给 WebSocket 设自定义头——这是规范级的封死。

换成 Python 也没用：Pyodide 里跑 `edge_tts`，底层仍是浏览器的 WebSocket，一样被拦。**卡点在网络沙箱，不在语言运行时。**

### 三条可用路线与代价

| 路线 | 音质 | 代价 |
|---|---|---|
| 本机代理转 edge-tts（晓晓） | ★★★★ 最好 | 需要一个后台进程 |
| 页面直连在线 TTS（`<audio>`） | ★★ 中等 | 依赖公网，第三方接口可能变 |
| 浏览器自跑 ONNX 神经模型 | ★★ 中等 | 模型 60–150MB，须整包塞进页面；中文多音字易错 |

> 走 ONNX 这条路之前先验网络：HuggingFace / jsDelivr 在国内常见 `000`，届时模型只能内嵌，单文件版直接涨到 100MB+。**音质反而不如晓晓**，投入产出比很低。

### 三引擎 + `auto` 选路

```
auto  →  proxy（晓晓，最好） > online（在线，兜底） > browser（系统语音，离线）
```

`auto` 是默认值，用户永远不用手动切。启动后静默探一次代理端口（超时 900ms），把结果缓存。

```js
function activeEngine() {
  if (cfg.engine !== "auto") return cfg.engine;
  return proxyAlive ? "proxy" : "online";
}
```

### 在线引擎：`<audio>` 直连 + 双缓冲预取

媒体元素播放**不检查 CORS**，所以第三方 TTS 的 MP3 可以直接 `audio.src` 播，无需后端。

段间停顿是体验杀手。实测首次实现段间空档 **761ms**，原因是预取被占位元素挡住、下一段现下载。修法：

1. 建 **两个 `<audio>` 元素交替**：A 播当前段，B 同时 `load()` 下一段
2. `warm(i)` 里判 `if (!b.paused) return;` —— 别打断正在播的那只
3. **静音解锁用第三个专用元素**，否则它会占掉 A/B 的缓冲位，预取直接失效（这是 761ms 的真凶）

修完段间空档降到 **171ms**，基本听不出来。

```js
function warm(i) {                      // 预热下一段
  if (!chain || i >= chain.items.length) return;
  var b = audioEl(slot ? 0 : 1);
  if (!b.paused) return;                // 关键：别抢正在播的
  var u = onlineUrl(chain.items[i].text);
  if (b.__url !== u) { b.__url = u; b.src = u; b.load(); }
}
```

切句长度也影响首句延迟：在线引擎按 **96 字**切，比代理的 160 字出声更快。

### 后台隐形化：让用户感觉不到进程

代理要常驻，但不能让用户开终端。装成系统服务：

```
launchctl bootstrap gui/$UID ~/Library/LaunchAgents/<label>.plist
```

plist 关键项：`RunAtLoad` + `KeepAlive`（崩了自动重启）+ `ProcessType=Background` + 日志落 `/tmp`。

- 提供一个**双击即装**的 `.command`，装成败都要给出可读结论，失败自动退回 `nohup`
- **沙箱内 `launchctl bootstrap` 会报 `5: Input/output error`**，`osascript` 加登录项会报 `-10004 权限违例` —— 这类操作必须由用户在自己的终端里双击完成
- 卸载路径要写进提示：`launchctl bootout gui/$UID/<label>`

### 验收（必须用 WebKit + 真实鼠标点击）

无头 Chromium 加 `--autoplay-policy=no-user-gesture-required` 测不出 Safari 的自动播放拦截。用 Playwright **WebKit + `page.mouse.click()`**，并劫持 `window.Audio` 记录播放事件时间线：

```js
window.__AS = [];
const _A = window.Audio;
window.Audio = function (...a) {
  const el = new _A(...a); window.__AS.push(el);
  el.addEventListener('playing', () => window.__EV.push(['play', Date.now()]));
  el.addEventListener('ended',   () => window.__EV.push(['end',  Date.now()]));
  return el;
};
```

看三件事：`currentTime` 是否稳定递增、`paused` 是否 false、`ended → play` 的间隔（即段间空档）。

## 四、图注／习题里的数学：别手写 JS 字符串

书里的插图图注、习题答案常常带公式。把它们存成 JS 对象字面量再手写反斜杠，一定会出事：

```js
"6.7": "其中 $\log b$ 与 $\times A$ 与 $\rho$"   // ← 三处全废
```

JS 会把 `\t` 当制表符、`\r` 回车、`\n` 换行，`\l` `\x` 之类则是非法转义（有的直接语法报错）。
症状很隐蔽：页面能跑，只是某几条图注里的 `\times` 变成 TAB 后跟 `imes`，肉眼一时看不出。

**做法**：主表存 JSON（`caps-zh.json`，LaTeX 写单反斜杠），用一个生成器脚本产出 `caps-zh.js`：

```python
line = "%s: %s" % (json.dumps(no), json.dumps(text, ensure_ascii=False))
```

`json.dumps` 会把 `\` 正确转成 `\\`，顺带解决漏逗号、排序、分章注释。

**三道哨兵**，每批加完就跑（比人眼可靠）：

```python
[c for v in d.values() if any(ord(c) < 32 for c in v)]      # 控制字符 = 0
[k for k, v in d.items() if v.count('$') % 2]                # $ 必须成对
[k for k, v in d.items() if re.search(r'[¼þ]|Wve|Wrst|conWg|Xat', v)]  # OCR 乱码残留
```

**再加一道浏览器批量渲染**：把所有条目一次性 `MT.md()` 进 DOM，统计 `.katex` 节点数、
`.katex-error` 数，以及渲染后正文里是否还残留 `dfrac|nabla|rho|langle` 这类命令名
（残留 = 没进公式，或转义写坏）。434 条全过比抽十条有说服力。

**两套转义规则正好相反，别混**：

| 存放形式 | 源码里怎么写 | 理由 |
|---|---|---|
| JSON 主表（`*.json`） | `"\log z"`（单反斜杠） | JSON 的 `\\` 才是反斜杠，交给脚本时写单的 |
| JS 源文件（`data-cards.js`、`data.js`） | `"\\log z"`（**双**反斜杠） | JS 源码会把 `\p` 当转义吃掉，`\log` 变成 `log` |

在 JS 源文件里写单反斜杠的症状特别好认：页面渲染出 `2pii`（`\pi` 丢了）、
`delta` 是斜体单词而不是 δ、`log` 前面没有 operator 间距。看到这三种，就是反斜杠丢了。

还有一个连带坑：**批量把单反斜杠换成双反斜杠时，会把行尾的 `\n` 也变成字面量 `\n`**。
`vivid` 的四段是靠 `\n` 分行存的，换错之后整张卡变成一行。做法是先定位【例子】到【数字】
这一小段再替换，或者干脆整段重写，别做全文 `replace`。

改完的机械检查（比肉眼快）：

```js
// 渲染后正文里还残留命令名 = 没进公式或有反斜杠丢失
const plain = div.textContent;
if (/\\(pi|log|delta|frac|sqrt|theta)/.test(plain)) 记一笔;
```

**原文是 OCR 出来的怎么办**：PDF 转文本会吃掉连字（`five`→`Wve`、`first`→`Wrst`）、
把 `=` 变 `¼`、`+` 变 `þ`、`π` 变 `p`、`∂/∂x` 变 `]=]x`。这时候「翻译」不可能只翻文字，
必须连符号一起重建；而且 OCR 常把图注截断在 220 字符左右，译到断点为止标「（原书图注在此截断）」，
不要替作者续写。

## 五、长文强调：三层，且每层都要能量出来

楷体长文读久了会「滑」——眼睛在走，脑子里没落点。加标注别靠人工标几十章，先用**已有数据 + 句式规则**去找：

| 层 | 来源 | 判据 | 每页上限 | 样式 |
|---|---|---|---|---|
| 重点句 | 定义 / 卡点 / 论断 | `(是指\|指的是\|称为\|叫做\|叫作)`；折叠区引用的那句；`^(因此\|所以\|可见\|于是\|…)` | 2（定义、卡点各 1） | 加粗 + 极淡同色底 |
| 转折 | 然而 / 但 / 其实 / 恰恰 / 并非 … | 前面须有句读或在句首 | 2，每段 1 个 | 只染词，不加底 |
| 术语 | 中文里的「…」 | 章内首次出现 | 不限 | 青色，首次带点线 |

**四条硬约束**（都是量出来的）：

1. **≤70 字**。正文一行约 45 字，100 字＝四行整片荧光笔，比不标注更累。实测把上限从 100 收到 70，
   `>60 字` 的重点句从 25% 掉到 2%，覆盖率只从 84% 掉到 72%——这笔交易划算。
2. **必须收在句末标点**。以「；，：」收尾的分句单独上底色像半句话（例外：≥22 字的分号句可以留）。
3. **同句不重复标**。一句既触发定义又触发卡点时，不去重就会套两层底色。
4. **转折词前面必须是句读**。否则「不但」「但凡」「岂但」全被误伤成转折。

**包裹用 `range.extractContents()`，不要 `surroundContents`**：后者在跨到半截元素时抛错，
如果退回「逐文本节点切分」的兜底，一句话会被切成好几段碎片（验收脚本里会看到 `.key` 里是「，」「可写作」这种残句）。
extract + insertNode 永远只出一个 span，而且句子中间夹的公式会被一起包进去，底色不断。

还有两个坑：每标一处都要**重建文本地图**（切分文本节点会让上一次的节点引用失效，报
`parent.insertBefore of null`）；建图时**不要把 `.key/.turn` 跳过**，跳过会让后续偏移全错位。

验收别靠眼看：遍历整章所有页，断言「每页 ≤2 句、≤70 字、收在句末、无嵌套、零 JS 错误」。
50 页的一章最终落在 35–45 个重点句、10–20 个转折词、50–80 个术语，这个密度读起来才不吵。

## 六、公式引擎的加载顺序（一个很安静的 bug）

`math.js`（转换层，26KB）和 `katex.min.js`（渲染层，600KB）经常被一起塞进懒加载。
但**转换层必须在首屏**，只有渲染层值得懒加载。否则：

- 地图、卡库、复习、学伴的第一屏都调 `md()`；`MT` 不存在 → 全部走 `esc(t)` 兜底
- 页面看起来"正常"，只是所有公式都变成 `(2πi)^(−1)log z` 这种源码
- 更糟的是，`ensureMath()` 里常写 `if (window.MT) return` —— MT 一旦存在就不再拉 KaTeX，
  **KaTeX 永远不会到**，公式永远是纯文本

正确的分工：

```html
<script src="math.js"></script>   <!-- 首屏：只做 Unicode→LaTeX 转换 -->
<!-- KaTeX 仍在按需清单里，进章节/进复习时才拉 -->
```

`math.js` 里的 `KX` 不能在 IIFE 时定死，要每次渲染现取：

```js
var K = root.katex || KX; if (!K) return null;
// 并且 ready 要做成 getter，否则 MT.ready 永远停在 false
Object.defineProperty(MT, "ready", { get: () => !!(root.katex || KX) });
```

还有一处：复习页不走关卡的按需加载器，所以**进复习页要主动 `ensureMath()`**，
取回后原地重绘当前卡（别重建队列，否则刚答过的几张会重新排一遍）。

顺带一个排版判据：`compact`（闪卡）模式下**不要让长公式升成独立块**。
一句话被两个块公式切成三段，读起来像小标题串联；留在句子里反而顺。

打包单文件版时别忘了同步：`math.js` 要放进 CORE_JS（跟 index.html 的首屏脚本列表一致），
不能留在懒加载清单里。改完用 `file://` 打开单文件版验一句 `MT.ready === true`
（单文件里 KaTeX 是内联的，ready 必须是 true；为 false 说明加载顺序又错了）。
