# 机制实现清单

脚手架（`assets/scaffold/`）已实现下列全部机制。从零写时照搬逻辑；改脚手架时不要破坏这些不变量。

## 一、已学状态与初见面（硬规则 2）

每张卡有 `learned` 布尔。两个点亮途径：

1. **教材通关**：`setLevelResult` 在 `pct>=80` 时调用 `applyLessonTeaches(levelId)`，把该教材 `teaches` 里所有卡标记为已学。**未达 80% 不标记**——读一半不算学过。
2. **初见面**：队列或关卡里撞到未学卡时，直接摊开 `vivid` 完整解释，按钮写「我读过了，考考我」，**隐藏评分按钮**。点击后 `markLearned`，背面收起，转入正式自测。

**不变量**：
- 未学卡**绝不能**出现评分按钮
- 已学卡**绝不能**预摊答案（背面必须默认收起）
- 关卡闪卡选题优先取已学且未进过调度的卡，不足时才补未学卡（走初见面）

## 二、SM-2 调度

```
答对(g>=3):  rep 0→iv=1; rep 1→iv=3; rep>=2→iv=round(iv*ef); g==5 再 ×1.3
             ef += 0.1-(5-g)*(0.08+(5-g)*0.02)，截断 1.3–2.5
             rep+=1, due = today + iv
答错(g<3):   rep=0, iv=0, due=today（当天回炉），lapses+=1
```

- 到期卡优先，新卡每日上限 20
- `due <= today` 才进队列
- 评分 1/3/4/5 对应 忘记/困难/良好/轻松

**不要在界面上暴露 EF 之外的内部量**，展示时说人话："间隔拉长到 8 天后再来""答错回炉，这张卡今天还会再出现"。

### 出卡范围：只放行「读完的章节」（容易漏的一条）

`dueCards()` / `newCards()` **不能**直接从全库 `DATA.cards` 过滤 `seen/due`。
那样等于按题库顺序发卡：前面几章的卡答完，指针自然滑到下一章，
**用户还没读到第 9 章，今日复习里就冒出「超函数的定义」**——这不是复习，是没有上下文的预习。

```js
function openedChapters() {            // 已通关关卡 → 章节号集合
  var set = {};
  DATA.levels.forEach(lv => {
    var rec = S.levels[lv.id];
    if (rec && rec.done && lv.chapter) set[String(lv.chapter).replace(/^ch/, "")] = 1;
  });
  return set;
}
function openCards() {                 // 队列的唯一来源
  var open = openedChapters();
  return DATA.cards.filter(c => open[String(c.ch)]);
}
```

- `dueCards` / `newCards` / `unlearnedCount` 三处都要走 `openCards()`，缺一处就会漏
- 用 `done` 而不是 `learned`：初见面会 `markLearned`，拿它当闸门等于没闸门
- 历史脏数据（老版本已把未读章节的卡标了 `seen`）也会被挡住，不用清 localStorage
- 空态要分开写：**没有通关任何章** ≠ **今天复习完了**。前者引导去读，后者说「明天再来」
- 空态时把「显示答案」**和「跳过本张」一起藏掉**——没有卡可跳的时候留着那颗按钮很傻
- 没有章节结构（只有区域级教材关）的脚手架版，闸门按 `lv.r` 聚合：`openedRegions()`，
  配了教材关的区域必须教材关通关，没配的退化为「任一关通关」

### 卡面文案的两个小口径

- **到期天数不要出现负数**。`due - today` 为负说明已经过期，写成「已到期 3 天」，
  不要写「-3 天后」。
- **队列提示要交代范围**。「到期卡 37 张 · 可领新卡 0 张 · 出卡范围：读完的 8 章，共 37 张」——
  这一行能直接回答用户「为什么我的卡变少了」，省掉一轮困惑。

### 验收怎么写

别只测「有卡」。三组状态一起测：

| 状态 | 期望 |
|---|---|
| 一章都没通关 | 队列空、卡面说「还没有可复习的卡」、评分行与跳过键都隐藏 |
| 只通关第 1 章 | 队列里**只有**第 1 章的卡；把第 2 章以后的卡强行标 `seen>0` 也不出现 |
| 再通关第 2 章 | 第 2 章的卡出现，第 1 章的卡带着原间隔继续 |


## 三、元认知校准

- 每题作答前先选 1–5 把握度（`predict`），提交时把 `predict` 与 `correct` 一起记进日志
- `校准误差 = |predict/5 − (correct?1:0)|` 的均值
- 复盘墙展示当前误差与样本量；样本 <6 时不给结论

## 四、错因统计

日志里记 `mtype`（事实缺失/规则误用/条件误判/表达不清），复盘墙出分布条。

- BOSS 关判别错 → `条件误判`；做法错 → `规则误用`
- 错因关选对也记一次（记正确类别），用于观察用户接触过的错因类型
- 提示语要点明：**知识性错误占比下降才算真进步，表达类下降可能只是熟练度**

## 五、XP 与成就

**XP 只能授予提取类行为**：

| 行为 | XP |
|---|---|
| 凭回忆答对（闭卷简答，未用提示） | 10 |
| 用了提示后答对 | 5 |
| 费曼讲解通过 | 14 |
| BOSS 判别+做法全对 | 12 |
| 教材出门检查答对 | 6 |
| 卡片评分 4/5 | 6–7 |
| 未学卡初见面读完 | 2（只给极少的参与分，且不计入通关） |

**看材料、翻页、点按钮：0 分。**

成就示例：初次提取、调度启动（10 张卡进调度）、讲明白了、BOSS 克星（80%）、校准合格（误差 ≤0.2）、三日连胜、全境通关、先学后练（读完 6 篇教材）。

## 六、关卡解锁

线性解锁：前一关 `done`（≥80%）才解锁下一关。

**顺序必须由内容层的 `DATA.levels` 数组定义**，且满足「同区域 lesson 在训练关之前」。解锁判断用数组下标，不要在代码里硬编码关卡 id——内容与引擎要解耦。

## 七、掌握度

按区域算：`iv>=21` 记满分，否则 `min(iv/21, 0.9)`，每张卡再扣 `lapses*0.15`，取均值映射到 0–100。

它是**调度成熟度的代理**，不是能力测量。界面上别说成「正确率」。

## 八、数据导出（必须提供）

- **Anki CSV**：`front,back,type,example` 四列，背面用简短答案便于导入
- **学习日志 JSON**：完整 state，便于换设备/换实现

导出是防平台锁定的底线，不能省。

## 九、连胜

- 按自然日判断，跨天 +1；断 1 天以上归 1
- 日历展示近 14 天
- 连胜是**参与指标**，不要当成学习成果炫耀——文案上要克制

## 十、AI 学伴面板（本地规则引擎）

两种模式：

- **只追问**（默认）：检测长度不足 / 术语未落地 / 缺例子 / 缺因果，然后反问。不给答案。
- **批改**：对照本题 `keys` 指出缺失，提示"我给的反馈不算你的产出，重写一遍才算完成"。

本地规则引擎的好处：离线、可复现、不会幻觉。**真 AI 的用法放在提示词库页**，让用户复制去用。

## 十一、测试不变量（改代码后必跑）

```
全新进度 → 直接进最靠后训练关：进不去（被教材关挡住）
全新进度 → 进「今日复习」：队列为空，卡面说「还没有可复习的卡」，评分行与跳过键都隐藏
教材通关 → 再进「今日复习」：只有该区域的卡；其他区域的卡即使 seen>0 也不出现
教材通关 → 该区域所有卡 isLearned=true
教材未通关（<80%）→ 不标记
跨区域标记 → 不允许（lessons.teaches 必须同区域）
全部卡 → 都被某篇教材 teaches 覆盖
卡片 vivid → 含【一句话】【类比】，且含【例子】或【数字】
```
